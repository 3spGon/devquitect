# Targeted Refactoring

Improve existing code structure through a justified, behavior-preserving change. Use this skill for explicit, bounded refactors and reviews; use [the workflow reference](references/workflow.md) for evidence, authorization, implementation, and verification rules.

Do not use it for feature work, speculative cleanup, architecture or API redesign, migrations, dependency changes, or unrelated style edits. Reviews and plans do not authorize edits. Persistent design and multi-slice implementation belong to `$software-idea-to-project` and `$project-plan-execution` after their approval requirements are met.
